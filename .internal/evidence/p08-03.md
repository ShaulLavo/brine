# P08-03 UDP rendering and runtime evidence

Recorded November 1, 2026. This change stages isolated UDP rendering and runtime
parsers. The planner remains conflict-only. Host/apply execution, recovery,
resolution and store release guards remain enabled. It does not activate UDP
deployments, readiness, status or lifecycle operations.

## Renderer and observation checks

IPv4 and bracketed IPv6 unit goldens preserve the complete HTTP-only unit and
add only the explicit approved UDP publication. Allocation checks cover the
canonical endpoint, grant app/hash/range, exposure, container port, client
address and identical `Plan.UDP.Next` and `Quadlet.UDP` payloads. The
reconstructed desired spec includes UDP. Missing, duplicate and mismatched
payloads refuse.

Runtime tables require one exact loopback TCP binding and at most one exact UDP
binding. UDP requires observed pasta networking. Tests reject extra bindings,
extra TCP/UDP mappings, unknown protocols, wildcards, mapped or scoped addresses,
invalid/noncanonical ports, stopped containers and wrong unit/container identity.
Unpublished image `EXPOSE` entries remain allowed. Pinned unit parsing and
runtime-to-unit comparisons cover both address families and endpoint drift.
HTTP-only goldens and collector behavior remain unchanged.

New negative tests first failed on client-address binding, nil/duplicate payloads,
network-mode validation and pinned UDP parsing. The earlier draft's full CI
failure came from the production collector lifecycle fixture using the old
literal inspect command. Its key and pasta response now match the real collector;
no lifecycle assertion was removed or changed.

## Isolated arm64 runtime

unprivileged rootless runner. The test used the real Quadlet generator, manager,
systemd user service, Podman inspector and production inventory collector.
The fixture has no app secrets, capabilities, mounts, Caddy route or network-mode
overrides. It makes no UDP protocol or remote client claim.

Both `127.0.0.1:24431:7777/udp` and `[::1]:24431:7777/udp` matched actual inspect
facts beside `127.0.0.1:20431:8080`. Observed networking was exactly `pasta`.
HTTP health returned the pinned fixture body. The real collector matched the
rendered unit hash and proved the TCP forwarding socket's PID/start-time,

The current physical test does **not pass**. The production `ss -H -lunpe`
command sees the exact UDP socket and pasta PID/FD but supplies no inode on this

module. Missing inode evidence stays unknown. The test deliberately refuses
success rather than claiming affirmative UDP ownership. No host/kernel repair
has been applied. The prerequisite and proposed next step are reported privately
to the coordinator.

The first setup attempt correctly distinguished the index digest from the
selected manifest; the harness now uses Brine's existing pinned inspector.
A second attempt refused the ordinary test user's pre-existing group-writable
configuration directory before unit installation. The fixture then used the
already enrolled runner's protected directories without relaxing permissions.

amd64, public networking, protocol sessions and lifecycle fault drills remain

## Cleanup and rerun

`integration/run-udp-runtime.sh` installs outer teardown before running the test.
The Go fixture registers resource cleanup before pulling an image or installing a
unit. The outer trap verifies the recorded unit hash before fallback removal,
keeps pre-existing image IDs and checks task socket absence. No blanket prune is
used. The controlling fleet job holds the shared Pi reservation and checks the
owner-busy flag before staging and execution.

Every physical attempt verified task unit/container/socket removal on the real
host. Existing runner containers and images remain at their pre-run counts of
three and eight. Transferred test executables, scripts and task scratch were
removed. No policy, Caddy, firewall, DNS, access settings or kernel module changed.

Build a test binary with `GOOS=linux GOARCH=arm64 go test -tags udp_runtime -c
-o <task-directory>/udp-runtime.test ./integration`. Put the host wrapper beside
it in an owned scratch directory on the explicitly authorized host. Run the
wrapper as the unprivileged runner with `BRINE_UDP_RUNTIME_TEST=1`. The fleet
controller, staging and cleanup transcript are private review evidence, not
production deployment instructions.
