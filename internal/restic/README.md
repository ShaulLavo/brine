# Encrypted archive transport core

This package transports a private staged capture through pinned restic 0.19.1. It does not capture a live native engine, verify native replay, start a service, release a fence, or authorize publish, restore, retirement, or purge. P09-05 remains open until those managed operations and real remote acceptance ship.

`Seal` produces a deterministic USTAR envelope. Its canonical manifest binds the database binding, epoch, capture, module artifact SHA-256, and control checkpoint SHA-256. The envelope contains `manifest.json`, a synthetic `data` directory, then the exact sorted manifest members. Members have private modes, normalized relative paths, byte sizes, and SHA-256 hashes. Directories use mode 0700 and files use mode 0600. Links, devices, foreign ownership/devices, special modes, traversal, unsupported names, PAX/GNU extensions, duplicates, extra members, corrupt bytes, quota overflow, and unexplained physical tails refuse. Native hard-linked input must first be staged as independent ordinary files.

The default limits are 64 MiB of member content, 32 MiB per file, 72 MiB for the complete envelope, and 8192 members. Explicit limits remain capped. No archive is held in memory. The codec checks the expected physical archive length and its two zero trailer blocks before extraction, then verifies the complete member set into a fresh private root.

`NewClient` fixes the production executable to `/opt/brine/restic/0.19.1/restic`. Its SHA-256 comes from the protected enrollment record. Every tool call checks immutable root-owned parents, the exact executable mode/hash, and the version before accessing private repository material. This unit supplies no installation or enrollment pin. The local gate uses a package-test-only override to the separately inspected root-owned `/usr/bin/restic`; production has no alternate-path argument.

`NewS3Repository` accepts a privately delivered recovery password and the existing scoped `backupcredentials.Packet`, including an optional session token. The location supports a HTTPS endpoint, bucket/prefix, region, and fixed path-style option. The destination hash must match the supplied location. Binding/epoch, credential and recovery versions, and a finite lease expiry remain in its immutable scope. Repository/location formatting and JSON redact private values. Secrets and endpoints enter only the explicit child environment, never argv, returned errors, or evidence. Ambient cloud profiles, proxies, credentials, home, and cache are absent.

A required `RepositoryAdmission` adapter re-reads protected destination ownership, exclusive lease, current scope/epoch/credential lifetime, and the separately reviewed creation grant under the caller's existing locks. A valid hash or caller path alone supplies no authority. The core has no production host/store adapter, so it cannot be wired directly to an untrusted request. This is the only admission interface; there is no backup daemon or second operation engine.

The tool commands are fixed:

- `Init` runs `init --repository-version 2` only with the reviewed new-owned-repository scope and creation grant.
- `Backup` runs `backup --stdin --stdin-filename brine-archive.tar --host brine --tag brine-capture-<capture ID>`. It checks the sealed envelope before and after the command. Incomplete/nonzero output returns no point.
- `InspectExact` runs `ls <full snapshot ID>` and requires the exact selected snapshot and single regular archive object with the expected size.
- `InspectCapture` runs a bounded `snapshots --tag brine-capture-<capture ID>`, requires exactly one result, then inspects its full snapshot ID. It resolves an interrupted write without selecting `latest` or repeating the write. Missing or duplicate results refuse.
- `RestoreExact` runs `dump <full snapshot ID> /brine-archive.tar` into a quota-bound private file, authenticates restic content, checks the complete envelope hash/size, and performs strict member extraction. It checks the exact snapshot first.
- `Check` runs `check --read-data` and accepts only a clean structured summary. It is a bounded-deadline repository check, not a native-data receipt.

Every call uses `--no-lock --no-cache`; JSON calls also use `--json`. The admission adapter must prove one managed owner and serialized repository access. `--no-lock` avoids granting repository lock/deletion writes to isolated readers. It does not make multiple writers safe. No API exposes arbitrary arguments, `latest`, key changes, repair, unlock, mount, forget, prune, provider deletion, or remote administration.

Tool calls require a caller deadline of at most thirty minutes that fits the credential lease. The streaming runner discards bounded diagnostics, never inherits an environment, and cancels the owned process group on timeout or stream quota failure. A launched interrupted write returns `ErrUnknown`. Malformed successful mutation output also returns `ErrUnknown`; a snapshot may exist even without a result. The caller must inspect the owned capture before deciding how to resolve it. Failed checks preserve source state and never produce startup or mutation authority.

`TransportPoint` records an exact repository reference and expected archive identity. `Backup` and `InspectCapture` do not prove authenticated remote member equality. Only a successful `RestoreExact` proves the selected archive and members match. Even that proof is transport evidence only. Full-state native replay, source coverage, signing recovery, retention, operation journal, fences, and source drift checks remain higher-layer requirements. Missing recovery material never generates a new owner or signing identity.

The unit and process tests cover member attacks, quotas, mutable evidence, strict manifest and JSON decoding, scope/expiry mismatch, pin refusal before secret access, ambient-environment exclusion, interruption, and actual descendant cleanup. Run the optional actual local gate with `scripts/check-restic-core.sh`. It creates and removes a disposable encrypted local repository, checks exact snapshot/member equality and duplicate/corrupt refusals, and prints only scrubbed hashes. It does not use S3 credentials, access the Pi, or prove native recovery.
