## Earlier real-storage gate

`TestRealStorageRestore` passed in 8.51 seconds against real S3-compatible storage using the checksum-verified amd64 Litestream 0.5.17 binary and temporary credentials. The gate performed three isolated restores:

- Exact LTX TXID 1 after a successful private `sync -wait` barrier reported local and replica TXID 1. One independently committed sentinel row was recovered.
- A create-only SQLite snapshot, with independent hash/size verification and the same sequence/marker/commit-time row.
- An affirmative empty SQLite snapshot with the reserved empty schema proof.

Integrity, zero foreign-key violations, declared invariants and schema checks passed. All loss windows stayed unknown. Cleanup deleted only the five objects created under that gate's own disposable prefix and verified it empty.

The gate used a test-only fixture observer and rendered its own config. It did not prove production systemd units, enrollment, Pi mapping or the production prefix renderer. That is why it missed the #85 double-slash defect. The later connected Pi restore supplies those runtime/observer checks. The gate uploaded snapshots with conditional PUTs, but did not race two contenders. The Pi's empty initialization additionally passed production CreateEmptySnapshot's sequential create/second-create-refusal check. Neither proves the required competing-upload race.

The failed earlier gate attempts found a version-output expectation mismatch, stdout logging that broke JSON parsing, and a fixture multi-statement parameter-binding error. The first two were corrected in the delivered pinned-tool/config checks. Separate fixture inserts fixed the third. None is evidence that a successful upload barrier guarantees the last application write.

## Known limits and next drills

- Test a distinct digest-pinned image replacement separately. The persistent update changed environment only.
- Scope-negative, outage, expiry, destination-exclusion and retention tests need separately authorized disposable fixtures. Use existing private target/credential configuration; do not publish it.
- Preserve the interrupted initialization receipt and inspect before resuming. Never replay unknown SQL, clear an unknown fence or retry an irreversible swap blindly.
- Prepared-only removal still returns no-op without retiring its incarnation/reservations. Initialized persistent removal refuses with `persistent_archive_required`. Implement P04-08's exact archive model rather than delete directories or release reservations manually.
- Live restore and existing-schema migration automation are not shipped by these drills. No prior-epoch-safe DB swap has been proved.
- The early double-slash fixture stayed stopped with data/backups retained. The recovered fixture was stopped with independent replication retained. The fresh restore fixture remained healthy. Final stateless regression resources were removed without changing those persistent release heads.
- A server reboot is not a sudden-power-loss durability proof. One server is not high availability. Deployment/restore downtime is not zero downtime.
- Litestream is asynchronous. TXID recovery and sentinel checks prove the selected restored point, not zero loss of the most recent writes. Schedule periodic verified restores and keep loss windows unknown without independent last-commit coverage.
- An operator with direct host privileges can bypass Brine. Injected fences, probe units and manual failed-flag clearing are explicitly identified above; they are not autonomous production authority evidence.
