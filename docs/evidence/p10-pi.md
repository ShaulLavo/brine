# Phase 10 easy-data acceptance audit

Recorded 2026-10-11. Audited `origin/main` at `b0a7de7956d4249cae6f8086a7a3ab0dcdf3ce59` against the implementation, tests and recorded Pi receipts.

**P10-01 through P10-05 pass their stated acceptance clauses. P10-06 remains open.** The ordinary first deployment, container environment, remote replication and exact-sentinel restore passed physically. The alternate SQLite-build check was dropped by owner decision on 2026-10-11; it was not tested. The recorded client kills cover three completed-stage checkpoints, not interruption inside every detached step or during the final release. Archive recreation reached new preparation and credential activation but not initialization or a healthy replacement release.

## Evidence boundaries

The authorized target was the test Pi (arm64, Debian 13), with rootless Podman 5.4, systemd, Caddy and pinned Litestream 0.5.17. The fixture used a digest-pinned SQLite app image and real S3-compatible storage with externally supplied scoped credentials. Brine's restricted client drove deployment, initialization, status, restore, archive preparation, retirement and abandonment. Operator scripts installed the recorded binaries, supplied protected evidence, inserted synthetic fixture rows and injected client kills and listener conflicts.

This audit read all recorded `p10-*.json` and `p10-*.jsonl` receipts, the final verification set, the injection scripts, binary commit receipts and coordinator ledger. Earlier failures are not silently replaced by later success. No remote commands or new physical drills were run by this audit.

This is a scrubbed account for a public repository. Host and account identifiers, addresses, destination names, endpoints, prefixes, credentials and their paths, operation IDs and runtime identities are omitted. Source commit IDs identify Brine code, not the host inventory. Private receipts remain with the operator.

Before this phase, the operator intentionally backed up and reset Brine state. Stored pre-P10 plans lacked the new database-environment shape. Under the owner's no-version-skew rule, the drill used fresh state rather than adding old-plan compatibility. Backup verification passed; earlier data and state were retained, the root Caddy configuration was unchanged, and remote access was preserved. This reset is not evidence that old plans upgrade successfully or that an interrupted production installation recovers.
