- [x] **P03-07** Reconcile interruptions at every external effect boundary: killed job, lost SSH, unavailable Caddy, disk full, timed-out Podman call. Inspect real state before retrying; do not blindly replay partially completed steps.
  Unit evidence covers every forward and rollback intent boundary, uncertain launches, dead/live/pending runners, a real SIGKILL of a fake runner holding the SQLite host lock, lock refusal, read-only previews, proven-pull continuation without another pull, proven-install rollback after plan drift, and repeated reconciliation converging without more writes. Existing executor inspection helpers supply image, writer, artifact and commit evidence. Fresh plans resume only their uncompleted suffix; newer committed generations cannot authorize rollback. Missing staged-artifact or loaded systemd/Caddy generation evidence and interrupted rollback without its original route baseline stop at recovery-required. No automatic relaunch is allowed. Launcher creation and settlement hold a separate secure `launch.lock`, never the long-running deploy lock. Standalone reconciliation takes launch then attempts the host lock without waiting; contention releases launch before a bounded retry, so a waiting recovery job cannot block new apply acceptance. Once both locks are held, it settles launch-state records, and releases the launch fence before inspecting or resuming deployment work. Slow-launcher tests cover both the creation-to-intent gap and the unit-creation gap; apply acceptance remains prompt while another deploy holds the host lock. Commit settlement requires observed installed unit hashes (including retained units), image/platform, port, bound immutable secrets and Caddy file/generation, not merely a database release. Resumed preflight retains the executor effect deadline.
  The dispatcher accepts `reconcile` with exactly `{ "dry_run": true|false }`; only dry-run is read-only. Host wiring supplies `Server.Reconciler`. `Reconciler.ExecutorFor` constructs per-operation adapters using the stored plan and desired input. At run-op startup, after acquiring the host lock and before loading/executing its own operation, call `ReconcileUnderLock(ctx, lock, currentOperationID, false)` to exclude the current runner and avoid acquiring the same lock twice. This host-lock-only entry point deliberately defers queued and launch-unknown records unchanged rather than acquiring the launch fence in reverse order; standalone/boot reconciliation settles those records. Boot and standalone command entry points call `Reconcile(ctx)` instead. Production wiring now supplies the real reconciler through the host server factory, binds per-operation executor facts to stored desired input, and uses the run-op hook. The remote `reconcile --target NAME --dry-run` command and local `host reconcile` entry point share that engine. Preview initialization uses a bounded private read-only snapshot and existing fences, never creates/migrates source control state, and reports missing/older schema explicitly; tests compare source file bytes, modes and mtimes, including a live WAL and real v1 database. Remote mutation records a distinct planless reconciliation job and returns accepted plus an operation ID; the detached run-op worker excludes its own receipt and uses the fifteen-minute job deadline. Polling status exposes its kind, states and bounded events. Lock refusal before inspection/effects settles the receipt as failed with lock_unavailable; real unsettled outcomes remain recovery-required. CAS prevents duplicate execution; interrupted recovery receipts are inspected conservatively rather than replayed. Schema v2 migration preserves v1 deploy journals and foreign-key/append-only/state guards. Acceptance/worker tests prove observer expiration cannot cancel recovery, and resumed-health tests prove an effect deadline beyond fifteen seconds.
