# Phase 07: Drops and git previews

**Status: Approved** (owner, 2026-10-09). Design in [D9](../DECISIONS.md).

**Goal:** deploying a website takes one command or one `git push`. An agent that wants to show the owner something publishes a **drop**, a temporary static site or small server, and gets back a short link. Pushing a branch or opening a pull request produces a **preview**; pushing to main deploys production. Think Vercel-fast deploys, on our own server.

**Depends on:** enrollment and the Caddy adapter (Phase 02), the dispatcher (P02-02), and the apply engine and journal (P03-01 to P03-05) for server drops and previews. Static drops need only Phase 02 plus P03-01, so they can start before the rest of Phase 03 lands.

**Reference implementation:** mesh's temporary apps at mesh commit `78eeeaa`: `internal/apps`, `internal/apppill`, `web/app-pill` and `docs/temporary-apps.md`. That feature was removed from mesh, but the code stays in git history. Borrow designs and code from it. Keep its MIT notices (Solid, React Grab) with the pill.

### Tasks

- [ ] **P07-01** Wildcard routing and TLS spike. Pick how `*.shaulavo.dev` gets certificates. Option A is a wildcard certificate via DNS-01 with a scoped Cloudflare token, which needs a Caddy build with the Cloudflare module and so supersedes D2's distro Caddy for this host role. Option B is on-demand TLS with Brine as Caddy's `ask` endpoint, which stays on Debian's Caddy but is bounded by Let's Encrypt's per-domain weekly limits. Measure it, record the decision in DECISIONS, and route `*.shaulavo.dev` to the gateway.
- [ ] **P07-02** The drops gateway: one Brine-owned HTTP service behind Caddy that serves every drop. It handles private-access cookies, pill injection, traffic stamps, static file serving and proxying to server drops. It is a runner user service with bounded memory and connections, and it never exposes management actions to unauthenticated visitors.
- [ ] **P07-03** Upload packaging. Accept a single HTML file, a set of files, a folder, or a zip or tar archive. Detect `index.html` and single-page apps (fallback to index). Reject symlinks, unsafe paths, environment files and credentials. Limit size and file count (start from mesh's 64 MiB and 10,000 files). Upload streams through the dispatcher's bounded stdin. Store each drop under a Brine-owned directory by drop ID.
- [ ] **P07-04** Short readable IDs under `shaulavo.dev`, with a reserved-name list (apex, `www`, `api`, `admin`, `mail`, `brine` and any the owner adds) that drops and `--name` can never take. IDs are four lowercase characters like `7k3d`, from an alphabet without ambiguous characters), collision-free, never reused within a retention window. `--name` requests a readable name when it's free.
- [ ] **P07-05** Lifecycle. TTL is 24 hours from the last request: the gateway records traffic, and each request with a real visitor (not prefetch or bot noise, rule documented) extends it. `--keep` pins a drop forever; `brine drop keep|expire|delete ID` changes it later. A scheduled sweep stops and deletes expired drops under the host lock and journals the deletion.
- [ ] **P07-06** Visibility. Every drop starts private. The owner's link carries a one-time capability that the gateway swaps for an HttpOnly cookie on the drop's host, then redirects to the clean URL. Share sends a private view link that grants viewing, not management. Making a drop public is one-way, from the pill or `brine drop publish ID`, and needs a fresh confirmation (mesh's armed-button rule). After publishing, visitors get no management rights and the pill is hidden; any later change happens through the CLI. Delete works from the pill on private drops and from the CLI always.
- [ ] **P07-07** The pill. Port mesh's floating badge (Solid, Shadow DOM, edge snapping and dragging, keyboard docking, strict CSP) from `78eeeaa`. Actions: copy link, share, make public, delete, plus time left. The gateway injects it only into HTML responses for owners and private viewers. Browser tests in Chromium and WebKit, as in mesh.
- [ ] **P07-08** Server drops. A small server is either a digest-pinned image, or source plus a run command (`--run 'bun run start'`) on a pinned base image (Bun, Node, Python) chosen by policy. Each runs as a rootless container with tight CPU, memory and PID limits, loopback-only publishing, and no host mounts. Policy decides outbound network (default: allowed but rate-limited). Idle servers stop after a policy-set time and the gateway starts them again on the next request, with a short loading page. The number of running servers is capped per host.
- [ ] **P07-09** Commands: `brine drop create PATH [--run CMD] [--port N] [--keep] [--name NAME]`, `drop list`, `drop logs ID`, `drop publish ID`, `drop keep ID`, `drop delete ID`. All work in `--json` mode for agents. `create` returns the private link, the ID, the expiry time and the visibility. Add drops to the agent guide (P05-08).
- [ ] **P07-10** GitHub previews, using Actions first. Publish a GitHub Action, e.g. `brine-dev/deploy`, that builds in CI (static output, or an OCI image pushed to GHCR) and calls Brine with a CI deploy key limited by policy to that repository's app and its previews. Pushes to main produce a production plan, applied when policy allows auto-apply on main. Branches and pull requests produce a preview at `<branch-or-pr>-<app>.shaulavo.dev`. The Action comments the URL on the pull request and deletes the preview when the pull request closes. Previews get fresh empty data, never production databases (D8, D9).
- [ ] **P07-11** GitHub App, later: `brine connect github` installs an app so previews work without workflow files, through webhooks to a small Brine receiver. It needs its own security review (webhook signatures, per-repository scoping) before it ships.
- [ ] **P07-12** Abuse and safety limits for public drops: a per-host cap on public drops, request rate limits in the gateway, a size cap, a takedown command (`brine drop delete` works on any drop for the operator), and a security header set (no third-party cookies across drops, since each drop has its own host). Document what public drops are for and the operator's responsibility.

### Exit gate

On an enrolled host, `brine drop create ./site` returns a private short link within seconds. The owner can open it, share it, publish it and delete it from the pill. A server drop answers from a cold start. An idle drop expires after 24 hours without traffic, and traffic keeps it alive. A pull request on a test repository gets a preview URL comment, and merging to main deploys production. Expired and deleted drops leave no files, containers or routes behind.

**Evidence:** browser tests for the pill, a lifecycle test with an injected clock, gateway access-control tests (private, share, public, forged cookie, cross-drop cookie), an end-to-end run on the Pi or the VPS, and an Action run on a test repository.
