# Phase 07: Drops and git previews

**Status: Approved** (owner, 2026-10-09). Design in [D9](../DECISIONS.md). Unchecked tasks describe required behavior, not shipped guarantees.

**Goal:** deploying an owner-authored website takes one command or one `git push`. A drop is a temporary static site or small server with a short link. A branch or pull request gets a preview. Production still builds in CI and deploys through a separate credential.

**Prerequisites for every mutation:** Phase 02 enrollment, restricted dispatcher and runtime adapters, plus **P03-01 to P03-05 and P03-07**. This includes static uploads, capability grants, publish, TTL changes, cold starts, and disposal. Every mutation uses typed plan/apply authorization, freshness checks under the host lock, durable intent and journal, and unknown-outcome reconciliation. A request timeout never authorizes a blind retry. Read-only spikes can precede these prerequisites.

**Threat model:** only the owner's agents, scripts, and repositories supply code. Brine is not a third-party hosting service. Container, browser, and credential defenses still apply. Rootless execution alone does not prove isolation.

**Reference implementation:** mesh commit `78eeeaa`, especially `internal/apps`, `internal/apps/safety.md`, `internal/apppill`, `web/app-pill`, and `docs/temporary-apps.md`. Keep MIT notices with copied code. Borrow the management-origin separation and never-reassigned names. Do not copy its host-process runtime or bot-renewal rule.

## Tasks

- [ ] **P07-01** Decide gateway TLS and enrollment. Depends on Phase 02's Caddy contract. Compare wildcard DNS-01 with a pinned Cloudflare-enabled Caddy build against per-host on-demand TLS on Debian Caddy with a protected `ask` endpoint. Record certificate issuance limits, renewal, failure, and rollback evidence. The decision must list exact operator-confirmed enrollment changes and explicitly supersede affected D2 package/version checks and D4 fixed-global-config assumptions. DNS-01 requires a pinned binary/module and upgrade path, plus a protected, narrowly scoped DNS credential unavailable to drops and agents. On-demand TLS requires operator-owned global TLS configuration and a bounded `ask` service that authorizes only allocated, live names. Neither option grants agent DNS changes, app-supplied Caddy text, or a second import. This spike records a decision, not a live-host routing change.

- [ ] **P07-02** Add a typed gateway site and service. Depends on P07-01, P07-03, P07-04, and the mutation prerequisites. Extend the Caddy renderer and semantic/policy checks with a Brine infrastructure site inside the **same generation** as app sites. Use the existing single import, whole-root candidate validation, drift hashes, reload, and rollback/reconciliation. Preserve unrelated sites. Route the drop namespace and the reserved management origin to distinct gateway handlers, never to an app-supplied upstream. Refuse full-app routes anywhere in the drop namespace or at reserved names, including canonical aliases, wildcard and catch-all overlaps. Existing conflicting sites cause refusal, not takeover. Test app/gateway overlaps, unrelated-site preservation, drift, reload failure, and unknown reload outcomes.
  - Serve static files, proxy server drops, inject the pill, and check per-drop viewer credentials. Bound memory, connections, headers, requests, and streams. Never forward gateway credentials to upstreams.
  - Rewrite or strip every upstream `Set-Cookie` with a `Domain` attribute so accepted cookies are host-only. Refuse and strip upstream request and response cookies named `__Host-brine*`. Reserve that prefix for Secure, HttpOnly, host-only gateway cookies with `Path=/`. Test duplicate headers, casing, and malformed-cookie refusal.
  - Chromium and WebKit fixtures must exercise both server-set and JS-set cookies across two drops. Prove host-only isolation and server-side Domain rewriting, and explicitly capture the **accepted residual risk** of JS planting parent-domain cookies through `document.cookie`. Do not claim that sibling hostnames isolate all cookies. JS cannot create a valid Domain-scoped `__Host-` credential or acquire management authority.

- [ ] **P07-03** Package and admit uploads. Depends on the mutation prerequisites. Accept HTML, files, directories, and zip or tar archives. Detect `index.html` and explicit single-page fallback. Reject traversal, symlinks, hard links, special files, environment files, and credentials. Enforce both compressed/input and total **decompressed** byte limits, file-count and per-file limits before publication. Start with 64 MiB total output and 10,000 files, configurable downward by policy. Refuse decompression bombs and incomplete uploads.
  - Add a bounded upload protocol beside the dispatcher's current 64 KiB JSON request; do not silently expand that contract or embed arbitrary archives in it. Stage by immutable incarnation and artifact digest.
  - Check the destination mount, free bytes/inodes, ownership, and path components without following symlinks before setup or upload. Reserve capacity atomically under the host lock. Aggregate per-host byte/inode quotas include private and public drops, previews, staging, images, logs, tmpfs, and server writable storage. Keep policy-set free-space/inode reserves for production and control state. Reject exhaustion before effects and reconcile reservations after interruption. Test many small drops and concurrent admission, not only oversized single uploads.

- [ ] **P07-04** Allocate names and immutable identities. Depends on the mutation prerequisites. Allocate short lowercase names such as `7k3d` without ambiguous characters. Handle collisions by allocating another name, never overwriting. `--name` accepts a validated free DNS label. Names are **never reassigned**, including after expiry or deletion; keep a durable tombstone, with longer generated names when the short space runs out. Reserve the apex, `www`, `api`, `admin`, `mail`, `brine`, and operator additions. `brine.shaulavo.dev` is the trusted management origin. Bind tokens, cookies, jobs, paths, and cleanup to an immutable resource incarnation, not a name. Test collisions, exhaustion, reserved names, stale links, and forged or stale incarnation IDs.

- [ ] **P07-05** Implement lifetime and final disposal. Depends on P07-02 and the mutation prerequisites. TTL starts at creation and expires 24 hours after the latest qualifying visit. A successful authorized foreground GET navigation to drop content renews TTL. Public visits need no view credential. Denied requests, known bots, HEAD, prefetch, pill assets/status, management calls, subresource/API polling, and failed cold starts do not renew. An admitted stream or WebSocket handshake can count once only when it meets the navigation rule; stream bytes and frames never renew. Use documented request metadata and bot classification, not a claim to identify humans perfectly. Test every rule with an injected clock, including exact expiry, concurrent visits, and bot-classifier limitations.
  - `--keep` pins the resource until a planned `drop expire ID` removes the pin and starts a new 24-hour window. `drop keep ID` pins it later. Viewing does not undo deletion or expiry.
  - Drops and previews are disposable resources, **not D8 app archives**. They have no production mounts, secrets, or backup destinations. Their own dispatcher/policy scope authorizes final deletion or expiry, never app/archive purge. Plan and journal disposal under the host lock. Revoke access first, drain streams with a five-second deadline and terminate the remainder, stop writers, then remove managed data and runtime resources. Keep failure pending and reconcilable with serving disabled. Record completion only after absence checks. Retain only control audit records and name tombstones. Test interruption at each step, crash/reboot reconciliation, stale cleanup jobs, shared-destination refusal, and refusal to touch apps or archives.

- [ ] **P07-06** Separate viewing from management. Depends on P07-05, P07-12, and the mutation prerequisites. Every drop starts private. Publish, delete, and share browser actions run only on **`brine.shaulavo.dev`**, with server-checked owner authorization, exact Origin checks, CSRF tokens, and fresh one-use confirmation bound to the drop incarnation and action. Reject missing or hostile origins and stale confirmations. No management credential or authority exists on a drop host. Making a drop public is one-way. After publication, hide the pill and manage through CLI only, including deletion.
  - Owner capability links target the trusted management origin. View capabilities target a gateway-intercepted redemption endpoint on the drop host. These dedicated endpoints serve **no drop content**, upstream proxy, pill, or third-party resource. Consume cryptographically random, short-lived tokens atomically, bind them to role and incarnation, set Secure/HttpOnly/host-only `__Host-` cookies, and redirect to a clean allowlisted URL before serving content. Set `Cache-Control: no-store` and `Referrer-Policy: no-referrer` on redemption and redirect responses. Owner credentials stay at the management origin; drop cookies grant viewing only.
  - Set explicit policy TTLs for redemption tokens and view grants; share links expire and can be revoked, invalidating derived grants. Delete/expiry revokes all grants. Redact capabilities from Caddy/gateway access logs, operation logs, errors, and diagnostics. Test expiry, atomic concurrent redemption and replay, revoked shares, clean-URL redirects, referrer/third-party/upstream leakage, and log redaction. Hostile drop JS must fail management fetches, forged confirmations, and clickjacking. Deny framing on management/redemption pages with CSP `frame-ancestors 'none'` and compatible frame headers. Shadow DOM and an armed pill button are not authorization boundaries.

- [ ] **P07-07** Port the pill as UI only. Depends on P07-06. Port mesh's Solid/Shadow DOM badge, edge snapping, dragging, keyboard docking, and CSP, retaining notices. Show copy, share, make-public, delete, and time left for private owners; private viewers get viewing UI only. Management buttons open the trusted origin, as mesh did. Never embed management capabilities in drop HTML or pass them through opener messages. Strip the pill on public drops. Chromium and WebKit tests cover private pill-initiated deletion on the management page, view-only access, keyboard behavior, hostile page JS, and framing. Page code can imitate the pill, so the trusted confirmation page identifies the drop and requested action independently.

- [ ] **P07-08a** Spike server-drop egress enforcement. Depends on P07-01 and Phase 02 runtime contracts. Record the exact rootless network mode and enforcement mechanism, required operator enrollment changes, and denial tests on the pinned runtime. Preserve D4's host-loopback denial; ingress loopback publishing is not egress isolation. Block host addresses, private/tailnet/link-local/metadata ranges, the control plane, production databases, and other drops, for IPv4 and IPv6. Enforce destination checks at connection time and on redirects, robust to DNS rebinding and alternate IP forms. Test direct IPs, changed DNS answers, redirects, and raw connections, not just a URL validator. **Fail closed:** if enforcement cannot be installed, inspected, and tested, server drops get no network. If no-network mode cannot support safe gateway ingress, refuse server drops rather than permit egress. Do not weaken D4 or grant agents firewall/DNS access to make the spike pass.

- [ ] **P07-08** Run hardened server drops. Depends on P07-02, P07-05, P07-08a, and the mutation prerequisites. Accept a digest-pinned image or already-runnable sources on a policy-pinned Bun, Node, or Python image. Dependencies must be vendored or prepared in CI. No installs or compiles run on the host or implicitly at startup. Define `--run` as a serialized argv array, for example `--run '["bun","run","start"]'`; never evaluate it with the dispatcher or host shell. All user code runs inside the declared container.
  - Use rootless containers, no added capabilities, default seccomp, no privilege escalation, read-only root filesystem plus bounded tmpfs, CPU/memory/PID limits, writable-layer/storage quotas, and no sockets or host mounts. Uploaded code is copied into disposable container storage. Cap running servers and outbound bytes, connections, and destinations to prevent spam/scanning. Apply P07-08a's isolated egress or no network, never default unrestricted egress.
  - Inspect actual network mode and host listener bindings after start. Port preflight does not reserve a port. Unexpected listeners, failed inspection, or readiness failure abort publication and reconcile cleanup. Prove denial of Caddy admin, gateway control endpoints, runner secrets, production databases, and other drops. Test resource exhaustion and filesystem escape attempts.
  - Stop idle servers after policy-set idle time. Coalesce concurrent requests into one planned cold start, queue bounded requests, and return a bounded loading/error response. Use a 30-second startup deadline. Test cold success, crash, timeout, port race, inspection failure, and concurrent starts/deletion. A failed cold start must not renew TTL or return false readiness.

- [ ] **P07-09** Expose agent commands. Depends on P07-06, P07-08, and P07-12. Add `drop create PATH [--run ARGV_JSON] [--port N] [--keep] [--name NAME]`, `list`, `logs ID`, `share ID`, `publish ID`, `keep ID`, `expire ID`, and `delete ID`. Support stable JSON and no-input mode. Mutations return a plan; `--apply` combines plan/apply only when policy permits, without skipping the journal. Creation returns incarnation ID, private link, expiry, visibility, and operation ID after successful apply; capabilities appear only in the explicit private-link result, never routine logs or diagnostics. Add the contract to P05-08's agent guide.

- [ ] **P07-10** Add GitHub Actions previews. Depends on P07-09, P07-12, and production apply prerequisites. Build static output or an OCI image in CI, never on the server. Use **separate preview and production credentials**. The dispatcher enforces verb, environment, stable repository ID, and resource scopes for both plan and apply, independently of workflow input. Preview keys cannot request production plans, read/rotate production secrets, or touch production resources. Fresh preview data has no production mount, secret, or backup inheritance. Any preview-only secret needs its own explicit scope. Main deploys with the production credential under its own policy.
  - No fork-PR previews in v1. Fork jobs receive neither deploy rights nor secrets. Never combine `pull_request_target` with checkout/execution of fork content. Keep the privileged deployment step isolated from unchecked workflow inputs.
  - Derive DNS-safe hostnames from stable repository ID plus PR number and a short collision-resistant suffix allocated to the immutable preview incarnation. Branch text is display only, never a raw hostname/resource name or shell argument. Repeated pushes update the same live resource; a replacement gets a new incarnation and new suffix/name. Bind close-event cleanup to the exact stored incarnation, not whichever deployment occupies a label. Previews follow P07-05's final disposal rule. Test fork refusal, forged production plans/apply, secret access, branch injection and collisions, cross-repository deletion, delayed/replayed close events, and replacement cleanup. A fixture PR gets a URL comment; a main push exercises the separate production identity.

- [ ] **P07-11** **Deferred, excluded from the Phase 07 exit gate.** A GitHub App can remove workflow setup later. Depends on P07-10 and a separate webhook-signature, credential, and per-repository security review. Do not enable it as part of this phase.

- [ ] **P07-12** Gate public hosting on abuse and safety controls. Depends on P07-02, P07-03, P07-04, P07-05, and P07-08. This task must pass **before any public drop or public preview**, not after launch. Add aggregate capacity admission, per-host public caps, inbound request/stream limits, outbound spam/scanning limits, and tested security headers. Provide emergency suspend for an existing resource and a disable-new-public switch. Suspension revokes serving/access and stops writers without waiting for normal TTL. Journal requester, reason, incarnation, and outcome for suspension and takedown. Document phishing/abuse response and operator responsibility.
  - Record the accepted shared-domain cookie risk and the reputation risk to `shaulavo.dev`, including phishing, spam, browser blocklists, and certificate/domain limits. Protect the apex and reserved services. Production apps holding sessions should not use `shaulavo.dev` subdomains while drops share it. If third-party code is ever hosted, first move drops to a dedicated domain registered on the Public Suffix List and re-review the threat model. Test emergency controls, quota denial, outbound abuse limits, and all applicable negative browser/runtime tests above. Private drops remain subject to resource and isolation limits too.

## Exit gate

No task is checked until its implementation and acceptance evidence exist. P07-11 is deferred and does not block this gate.

- Use synthetic, committed fixtures. A 1 MiB/100-file static fixture with `drop create --apply` returns a private access link within **5 seconds after upload completion** on the recorded reference host. No build or certificate acquisition is hidden outside that measurement. Record hardware, package versions, certificate state, concurrency, and p50/p95 over 20 runs; require every run within the bound.
- Chromium and WebKit exercise view sharing, private pill-initiated deletion through the management origin, one-way publication, hidden public pill, and **public deletion via CLI**. All management authorization, cookie, capability, leakage, replay, hostile-JS, and clickjacking tests pass. The JS parent-domain cookie fixture records the accepted residual risk rather than a false isolation guarantee.
- A pinned server fixture answers within the 30-second cold-start deadline. Crash, timeout, failed inspection, port races, and 20 concurrent requests produce bounded outcomes and at most one start. Delete during startup/streaming cannot resurrect service.
- Injected-clock tests cover 24-hour expiry, pins, every qualifying/nonqualifying traffic class, and concurrent renewal. Final cleanup leaves no managed content, containers, listeners, or per-resource routes/grants; only audit records and never-reused-name tombstones remain. Interrupted cleanup and stale-ID tests pass without touching production or archives.
- All capacity, upload, Caddy overlap/drift/rollback, isolation/egress, emergency-control, and negative Action/dispatcher tests listed in these tasks pass. A fixture repository PR receives its preview comment; main deploy uses a separate production key. Fork and stale-close events cannot mutate resources.

**Host evidence may use the test Pi under D3's standing approval. Any other host, including the VPS, requires explicit owner authorization naming the target and the Phase 07 actions.** Unit tests and local browser fixtures use fakes/synthetic data. Record real-host and Action evidence separately after authorization. Mock tests do not prove working egress, certificate issuance, or live deployment.
