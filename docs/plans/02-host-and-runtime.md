# Phase 02: Enrolled host, Podman/Quadlet and Caddy

**Depends on:** validated spec/planner. **Goal:** support a single disposable fixture on one explicitly authorized Linux host. The authorized host is the owner's Raspberry Pi (Debian 13, arm64) within the limits in [D3](../DECISIONS.md). This is not authorization to modify the user's existing VPS.

### P02-01 evidence

The host-local collector returns the unchanged target snapshot and performs only reads. Machine-readable command output is collected from bounded stdout, separately from diagnostics. Active Caddy administration is checked independently of disk adaptation; malformed observations remain unknown. Linux file reads use nonblocking, no-follow opens and validate the opened object as a regular file or directory. Filesystem operations have context deadlines and a process-wide limit of eight outstanding workers, so even an uninterruptible kernel mount call cannot strand collection or create unbounded workers. Tests cover unrelated port owners, served domains, file-byte hashes, absent tools, failed probes, static imports and an off-loopback Caddy administration conflict. The test-only entry point is excluded from ordinary builds and CLI help. Its arm64 binary ran on the authorized Pi, strictly decoded its own JSON and passed snapshot validation. The binary was removed after the run. [Scrubbed snapshot](../../internal/inventory/testdata/pi-snapshot.json) and [probe fixtures](../../internal/inventory/testdata/pi-probes.json) retain the observed states and software versions, with synthetic identity, listeners, owner labels and disk capacity.

The Pi had no runner or active Caddy service. This verifies collection on Debian 13 arm64, not enrollment, a deployment or a working live Caddy route. Live Caddy tests use fake command responses. The collector adapts the root Caddyfile, enumerates static imports and compares the full adapted configuration against a read-only loopback administration request. Adapted JSON loses source provenance, so root domain attribution remains unknown when imports exist. Unreadable or dynamic imports and unavailable live configuration remain unknown. Quadlet image identity and allocated ports remain unknown rather than being inferred from intended configuration. Secret queries run independently of Quadlet existence when the current UID is the runner and expose names and IDs, never values. Unambiguous Brine-named secrets create secret-only app observations. A measured zero control generation and an empty unit set establish absent Brine deployment artifacts and allocations for those records, so the first-deployment planner can bind a preexisting secret. Existing or unknown control state keeps those deployment observations unknown. Ambiguous app/reference boundaries make the app set unknown instead of silently reporting an empty set.

The snapshot has no kernel, user-manager readiness or D7 home-ownership fields, so this task does not add them. It accepts an operator-provided stable identity HMAC key and a control-state generation reader. Until a control-database schema exists, a present state directory without that reader has unknown generation; a measured absent state has generation zero. Dispatcher wiring follows separately and uses `Collect(context.Context) (target.Snapshot, error)` without a dependency from inventory to dispatch.

### P02-04 evidence and integration boundary

`quadlet.Render` takes the verified normalized `policy.Desired`, recorded `plan.Plan`, and separately verified platform-manifest digest. It checks `DesiredHash`, so the redacted Quadlet payload in a serialized plan cannot replace the authorized input. The current planner image type records the index digest and platform, but has no selected-manifest field. The caller must verify the supplied manifest belongs to that index and platform before rendering. `Image=` pins the selected manifest; comments retain both digests, the platform, and plan hash. This package does not authenticate plans, authorize offline previews, or verify registry metadata.

Rendering uses fixed directives and sorted environment keys and secret bindings. It C-quotes each environment assignment and doubles percent and dollar signs for generated systemd commands. Newlines, carriage returns, tabs, quotes, backslashes, spaces, literal escape sequences, and ordinary Unicode round-trip. The spec boundary refuses other controls, uncommon Unicode whitespace, invalid UTF-8, NUL, and `${` expansion. New allocations stay in the policy range. Updates retain the planner's stable port when that range later changes.

The Linux filesystem manager stages mode-0600 units under `.local/share/brine/quadlet/staging`, outside `.config/containers/systemd`. Its validation interface requires a generator dry-run against that isolated candidate directory and verification that the expected service was generated. A failed validation, cancellation, candidate edit, or active-file drift prevents publication; a failed prepublication candidate remains available for a recorded retry rather than being silently deleted.

Overwrite authority comes only from the caller's committed `[]target.Unit` records in authoritative BrineState, never from host inventory or the ownership comment. A missing record permits creation only at an absent path. Existing bytes must match the committed hash before replacement; rollback uses the trusted receipt's installed and predecessor hashes. Unrecorded files, missing recorded files, and hash mismatches return a typed `OwnershipError` wrapping `ErrUnowned` or `ErrDrift`. Files must be regular, effective-user-owned, singly linked, and not group/world writable. Managed parent directories must also be effective-user-owned and not group/world writable; symlinks are refused, including parents changed between resumed steps. The operator-owned home itself is not changed.

`PrepareActivation` takes the rendered unit and committed records and returns an effect-free, serializable `Receipt`. Production apply must persist that intent before calling `AdvanceActivation`, then persist every returned state before advancing again. `PrepareRollback` and `AdvanceRollback` provide the same boundary for reversal. Receipts are trusted operation state, not app/client input. Convenience `Activate`, `ResumeActivation`, and `Rollback` loops do not implement durable journaling. The caller must hold D1's host mutation lock for the entire operation, including its journal updates.

States name pending path preparation, predecessor retention, candidate validation, rename/removal, active publication sync, source-directory sync, staging cleanup, and staging-parent sync. A failed fsync never marks its step complete. Every directory entry's parent is synced before relying on that path, including already-existing entries on retry. An identical retained backup is re-synced along with the rollback directory. Already-renamed, restored, or absent output must still pass pending publication syncs; matching bytes alone are not durability evidence. Cleanup refuses unexpected nonempty staging directories. The manager never reloads or starts services. Publication-sync failures return `ErrPublicationUnknown` with the receipt still pending for reconciliation.

### Exit gate

A documented, manually authorized fixture starts rootlessly, is routed through Caddy, survives a **full host reboot** (a user-manager restart doesn't count, per the spike), and is not dependent on an active Brine process. Conflicts with any unrelated service abort without changes. Privilege gaps are explicitly recorded.

**Evidence:** T05, T06, T11, T17. Pin exact Podman/systemd/Caddy versions and capture redacted test output. Before real deployment, confirm the owner has explicitly authorized the *specific disposable host*.
