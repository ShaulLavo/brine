# Phase 02: Enrolled host, Podman/Quadlet and Caddy

**Depends on:** validated spec/planner. **Goal:** support a single disposable fixture on one explicitly authorized Linux host. The authorized host is the owner's Raspberry Pi (Debian 13, arm64) within the limits in [D3](../DECISIONS.md). This is not authorization to modify the user's existing VPS.

### P02-04 evidence and integration boundary

`quadlet.Render` takes the verified normalized `policy.Desired`, recorded `plan.Plan`, and separately verified platform-manifest digest. It checks `DesiredHash`, so the redacted Quadlet payload in a serialized plan cannot replace the authorized input. The planner image type records the index digest, platform and selected-manifest observation. The caller must verify the supplied manifest belongs to that index and platform before rendering. A supplied digest differing from a known recorded manifest is refused. `Image=` pins the selected manifest; comments retain both digests, the platform, and plan hash. This package does not authenticate plans, authorize offline previews, or verify registry metadata.

Rendering uses fixed directives and sorted environment keys and secret bindings. It C-quotes each environment assignment and doubles percent and dollar signs for generated systemd commands. Newlines, carriage returns, tabs, quotes, backslashes, spaces, literal escape sequences, and ordinary Unicode round-trip. The spec boundary refuses other controls, uncommon Unicode whitespace, invalid UTF-8, NUL, and `${` expansion. New allocations stay in the policy range. Updates retain the planner's stable port when that range later changes.

The Linux filesystem manager has no durable receipts, publication states, or journal. `Install(context.Context, Unit, oldHash)` receives the rendered bytes/hash and the committed old unit hash from BrineState. An empty old hash means an absent unit. `Rollback(context.Context, unitName, installedHash, previousHash)` reverses the same operation; an empty previous hash means removal. The apply engine records intent and holds D1's host mutation lock across each call. Neither hashes nor intent come from app/client input, inventory, or the rendered ownership comment.

Each run verifies managed directory ownership and permissions, then reads the active hash. Bytes matching neither the committed old hash nor the desired new hash receive a typed `OwnershipError` wrapping `ErrUnowned` or `ErrDrift`. That refusal leaves active files and abandoned temps unchanged. Recognized old/new states permit cleanup of only that unit's reserved temporary namespace, followed by directory sync. Files must be regular, effective-user-owned, singly linked, and not group/world writable; managed parents must also be effective-user-owned and not group/world writable. Symlinks and unsafe parent replacements are refused. New directories are 0700, new files 0600, and every directory entry's parent is synced even when an earlier attempt left the entry present. The operator-owned home itself is unchanged.

Publication uses a complete file-synced same-directory temporary ending in `.tmp`, not an active `.container` filename. Generator validation still uses an isolated copy outside the active Quadlet directory. The validated candidate and live ownership binding are rechecked before replacement. A recorded active unit owns its reserved `<unit>.brine-prev` output slot. Updates atomically copy the old bytes into that slot and sync its file and directory before renaming the new candidate over the active file. The slot is replaced by the immediately preceding release on later updates, not by app-provided content. Matching backups are synced again on retry. Rollback verifies the retained slot against the committed previous hash and leaves that predecessor intact.

An active hash already matching the desired result still requires file and directory sync before success. A lost, unsynced rename/removal can instead leave the known old hash or expected absence; the same inputs reconstruct the candidate and safely replay the change. Partial reserved temps are discarded and rewritten, never treated as active ownership. Final active bytes are checked after publication sync. Invalid validation, cancellation, or drift prevents publication. The package never reloads or starts services; an uncertain publication is reconciled by rerunning the same intent rather than restoring a receipt state. The caller must not place operator files in the reserved backup/temp namespace.

### P02-05 integration evidence and Phase 03 boundary

The package in `internal/caddy` is the generation adapter, not an apply engine. P02-03 supplies command implementations. The [P02-06 fixture](../spikes/p02-06.txt) exercises the real reload-only polkit boundary, route persistence through two full host reboots, and container-to-admin denial through container loopback and both generated host aliases. Invalid candidates leave the prior route intact; a real failed reload rolls back. An injected lost acknowledgement after a real successful reload returns unknown, stops that manager and is reconciled by read-only disk/live comparison without a retry. Durable restart-time reconciliation remains Phase 03.

Local tests cover T11/T17 and the generation-files portion of T21. The read-only Caddy 2.6.2 probe accepted the renderer's multi-domain golden and whole candidate root, rejected a duplicate site with `ambiguous site definition`, and rejected an invalid directive with `unrecognized directive`. The probe used only temporary files and `caddy validate`; it did not start or reload Caddy. Its temporary directory was removed.

The main Caddyfile is passed as bytes and never modified. It needs exactly one standalone top-level `import /etc/caddy/brine/current/*.caddy` line: literal unquoted tokens, a single separating space, no continuation or trailing comment/argument. A Caddy 2.6.2 source-span tokenizer replaces only that path token; a byte-for-byte test protects all remaining operator content. Other tokens referencing the owned root, path-like snippet names, environment substitution and newer-version heredocs refuse before staging. **Other actual imports also refuse, including absolute paths:** externally imported snippets could shadow `current` on reload without shadowing the generation-path candidate. Refusing these imports avoids inspecting or trusting unowned files.

After validation, the same injected validator must run `caddy adapt --adapter caddyfile --config <candidate>` and return bounded JSON. A routing manifest of policy-validated `Site` values accompanies committed file hashes; the manager verifies its rendered bytes against the selected files rather than inferring authorization from disk. The adapted JSON must contain the pinned complete routes for every expected host and loopback port, and no stale host removed from the previous generation. Missing, duplicate, conditional or wrong-upstream routes refuse publication. Host checks walk only HTTP route matcher sets (including negation, nested subroutes and error routes), not unrelated logging fields or handler payloads. The read-only Caddy 2.6.2 validation/adaptation probe confirmed the multi-domain golden's exact route shape alongside an unrelated operator response; it touched only `/tmp` and removed its temporary directory. A follow-up read-only Caddy 2.6.2 adaptation captured a logging filter with a field named `host`; its independent JSON fixture proves that unrelated logging does not block publication. No live reload or served-state proof is claimed.

Enrollment must provide an empty `gen-0` and `current` before first publication. `Observe` returns hashes only; the operation engine must restore the routing manifest from committed desired state before applying a change. Crash states and the control-state/host-lock contract are documented in the package comment in `internal/caddy/doc.go`.
