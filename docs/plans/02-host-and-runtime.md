### P02-04 evidence and integration boundary

`quadlet.Render` takes the verified normalized `policy.Desired`, recorded `plan.Plan`, and separately verified platform-manifest digest. It checks `DesiredHash`, so the redacted Quadlet payload in a serialized plan cannot replace the authorized input. The current planner image type records the index digest and platform, but has no selected-manifest field. The caller must verify the supplied manifest belongs to that index and platform before rendering. `Image=` pins the selected manifest; comments retain both digests, the platform, and plan hash. This package does not authenticate plans, authorize offline previews, or verify registry metadata.

Rendering uses fixed directives and sorted environment keys and secret bindings. It C-quotes each environment assignment and doubles percent and dollar signs for generated systemd commands. Newlines, carriage returns, tabs, quotes, backslashes, spaces, literal escape sequences, and ordinary Unicode round-trip. The spec boundary refuses other controls, uncommon Unicode whitespace, invalid UTF-8, NUL, and `${` expansion. New allocations stay in the policy range. Updates retain the planner's stable port when that range later changes.

The Linux filesystem manager stages mode-0600 units under `.local/share/brine/quadlet/staging`, outside `.config/containers/systemd`. Its validation interface requires a generator dry-run against that isolated candidate directory and verification that the expected service was generated. A failed validation, cancellation, candidate edit, or active-file drift prevents publication of the candidate. Activation uses an atomic rename and directory sync, with a retained predecessor for rollback. It refuses unowned files, symbolic links, hard links, and symlinked parent directories. The caller must hold D1's host mutation lock across processes. The manager does not reload or start services, and a filesystem error after rename requires reconciliation.

### Exit gate

A documented, manually authorized fixture starts rootlessly, is routed through Caddy, survives a **full host reboot** (a user-manager restart doesn't count, per the spike), and is not dependent on an active Brine process. Conflicts with any unrelated service abort without changes. Privilege gaps are explicitly recorded.

**Evidence:** T05, T06, T11, T17. Pin exact Podman/systemd/Caddy versions and capture redacted test output. Before real deployment, confirm the owner has explicitly authorized the *specific disposable host*.
