# Phase 08: WebTransport applications

**Status: Approved** (owner requirement, 2026-10-10): "We must support WebTransport". This file schedules implementation. It does not claim working QUIC routing, a published fixture image, or host acceptance.

**Goal:** let an app, including a Rust game server for a Bevy wasm browser game, own WebTransport. Brine publishes its policy-approved UDP port, delivers app-scoped TLS files when requested, inventories ownership and uses proportionate readiness checks. Brine does not implement the game protocol or require every game server to implement a Brine echo service. HTTP health plus a UDP ownership check proves local deployment readiness, not a WebTransport session or external UDP reachability.

## Research findings

### End-to-end options

| Path | What actually terminates QUIC/TLS | Viability and cost |
| --- | --- | --- |
| Browser to Caddy HTTP/3 to existing HTTP app | Caddy | **Not a WebTransport path.** A successful HTTP/3 GET, WebSocket upgrade, or `transport http { versions 3 }` does not bridge WebTransport sessions. Debian Caddy lacks this feature. |
| Browser to WebTransport-aware Caddy to HTTP/3 app | Caddy on the front; app TLS on the upstream | Attractive target for shared UDP 443, certificate centralization and domain routing. No released support was found through Caddy **v2.11.7**. PR **#7669** implements experimental session bridging but remains **open, unmerged**, dependent on open PR **#7976**. Its manual loopback evidence is not our acceptance. Do not ship its moving branch as production support. |
| Browser to dedicated app UDP port | App | **Selected first delivery.** Rootless Podman publishes an unprivileged UDP port on an operator-approved address. Caddy still serves the ordinary HTTPS page/API. The endpoint URL includes its own port and certificate. Multiple apps get distinct ports, even on one address. No Caddy replacement or QUIC-aware proxy is needed. |
| Browser to UDP 443 SNI proxy to loopback app UDP | App | `caddy-l4` **v0.1.2** documents QUIC SNI/ALPN matching and UDP proxying. A custom Caddy build is required. It routes encrypted packets, not WebTransport sessions, and cannot enforce path, Origin, cookie or drop-view authorization. Its peer-address mapping has important multiplexing and migration limits. P08-09 must prove them before choosing it. |
| Browser to dedicated address UDP 443 | App, directly or behind an address-based UDP forwarder | Avoids SNI parsing and can separate apps by address. Needs operator-provisioned addresses and a privileged listener/forwarder; rootless publishing cannot assume access to port 443. Not the initial mode. Never lower the host's privileged-port threshold automatically. |
| Custom Go session bridge or another QUIC-aware proxy | Proxy front and app upstream | Technically possible with webtransport-go, but becomes a new security-sensitive reverse proxy. Do not build one merely to bypass the upstream gap. Any alternative must independently prove extended CONNECT, sessions, both stream directions and datagrams; generic UDP or HTTP/3 support is insufficient. |

**Hard blocker:** Debian's Caddy **2.6.2-12+deb13u1** and upstream stable **v2.11.7** do not provide the WebTransport session reverse proxy required for transparent Caddy-terminated shared-port hosting. The proposed implementation is experimental and unmerged. Updating Debian Caddy to the latest stable release alone does not solve it. The requirement remains feasible without writing a module through direct app-terminated UDP. Ship that bounded mode first; keep shared UDP 443 and gateway-authorized previews as explicit later gates, not silently unsupported deployments.

### Version and source evidence

1. [Debian trixie Caddy package](https://packages.debian.org/trixie/caddy) lists **2.6.2-12+deb13u1**, including amd64 and arm64. D2/D4's Debian baseline is therefore materially behind the experimental work.
2. [Caddy v2.11.7 release](https://github.com/caddyserver/caddy/releases/tag/v2.11.7), published **2026-10-03**, was the latest release returned by the upstream API. [Tagged HTTP transport source](https://github.com/caddyserver/caddy/blob/v2.11.7/modules/caddyhttp/reverseproxy/httptransport.go) marks upstream HTTP/3 experimental. [Reverse proxy documentation](https://caddyserver.com/docs/caddyfile/directives/reverse_proxy) describes `versions 3`, not WebTransport session bridging.
3. [Caddy PR #7669](https://github.com/caddyserver/caddy/pull/7669) was open and unmerged, last updated **2026-10-05**. Reviewed head **108053242eda829992a4f678ce51398b1bf3b7d8**. It proposes a global `servers { webtransport }` opt-in, HTTP/3 extended CONNECT detection and bridging of bidirectional streams, unidirectional streams and datagrams. Its backend uses TLS and HTTP/3 only. [Prerequisite PR #7976](https://github.com/caddyserver/caddy/pull/7976) was also open and unmerged, updated **2026-10-04**. Neither is a supported released configuration.
4. [Caddy global options](https://caddyserver.com/docs/caddyfile/options) gives default server protocols `h1 h2 h3`. HTTP/3 uses UDP independently of TCP HTTPS. `servers` belongs to the one root global block, not generated app site files. [Caddy v2.6 release](https://github.com/caddyserver/caddy/releases/tag/v2.6.0) made HTTP/3 on by default. Inventory must inspect actual configuration and listeners rather than infer readiness from the package version.
5. [caddy-l4 v0.1.2](https://github.com/mholt/caddy-l4/releases/tag/v0.1.2), published **2026-07-16**, is a non-core module; its README warns of breaking changes. [Its pinned go.mod](https://github.com/mholt/caddy-l4/blob/v0.1.2/go.mod) requires Caddy **v2.11.4**, Go **1.25.1**, quic-go **v0.60.0**. Debian 2.6 is not the build target. [QUIC matcher docs](https://github.com/mholt/caddy-l4/blob/v0.1.2/docs/matchers/quic.md) and [matcher source](https://github.com/mholt/caddy-l4/blob/v0.1.2/modules/l4quic/matcher.go) inspect QUIC/TLS hello metadata, including SNI and ALPN, without forwarding a terminated TLS session. The matcher uses an internal fake QUIC listener to inspect buffered packets. Treat matching cost, fragmented hellos and accepted QUIC versions as test cases, not assurances.
6. [caddy-l4 server source](https://github.com/mholt/caddy-l4/blob/v0.1.2/layer4/server.go) maps UDP associations by downstream **address:port**, with a default **30-second idle timeout**. It is not a connection-ID-aware QUIC router. Multiple connections to different names from one client socket, NAT rebinding and migration need explicit tests. A short-header packet arriving after mapping expiry cannot establish its original SNI route. [Server docs](https://github.com/mholt/caddy-l4/blob/v0.1.2/docs/servers.md) say a layer4 listener cannot also bind an HTTP-owned address. Current docs describe packet-connection wrappers; do not assume those exist in this tagged build. [Tagged listener source](https://github.com/mholt/caddy-l4/blob/v0.1.2/layer4/listener.go) says its listener wrapper does not support UDP. A separate layer4 UDP 443 listener must resolve ownership with the HTTP/3 listener first.
7. [webtransport-go v0.13.0](https://github.com/quic-go/webtransport-go/releases/tag/v0.13.0), published **2026-08-30**, implements **WebTransport-over-HTTP/3 draft-16**, per its [tagged README](https://github.com/quic-go/webtransport-go/blob/v0.13.0/README.md). Its [go.mod](https://github.com/quic-go/webtransport-go/blob/v0.13.0/go.mod) requires Go **1.26.0** and quic-go **v0.62.0**. Brine's Go 1.27 toolchain can build this candidate. [Go API](https://pkg.go.dev/github.com/quic-go/webtransport-go@v0.13.0) exposes `Transport.Dial`, `Server.Upgrade`, stream APIs, `SendDatagram` and `ReceiveDatagram`. It is usable for bounded real probes. Pin this version and test actual browser interoperability; a draft implementation is not proof of every browser revision.
8. [Podman 5.4 Quadlet PublishPort](https://docs.podman.io/en/v5.4.0/markdown/podman-systemd.unit.5.html) accepts explicit IP/host/container publishing and warns that omitted IP binds all IPv4 addresses. [Podman 5.4 run publish](https://docs.podman.io/en/v5.4.0/markdown/podman-run.1.html#publish-p-ip-hostport-containerport-protocol) supplies the `/udp` protocol suffix. TCP and UDP are separate allocations, not interchangeable health facts.
9. [Browser WebTransport constructor](https://developer.mozilla.org/en-US/docs/Web/API/WebTransport/WebTransport) requires a secure endpoint. Certificate-hash mode requires a short-lived X.509v3 certificate valid for less than two weeks, no RSA, and a trusted way to deliver the hash. It is not a substitute for normal production certificate lifecycle. [Tailscale Serve](https://tailscale.com/kb/1242/tailscale-serve) is not an arbitrary UDP WebTransport ingress. Use direct tailnet connectivity and an allowed host UDP listener; HTTPS Serve reachability alone proves nothing about QUIC.

### Reproducible real local protocol test (T25)

Run from the repository root. On the shared workstation, put these Go commands through the heavy-job queue. `scripts/check.sh test` also runs this isolated module, its race test and both Linux and Darwin vet checks. `scripts/check.sh lint`, `format`, `structure` and `vulnerability` retain their production gates; lint and vulnerability additionally check the experiment module. All experiment code is test-only, so there is no production reachability exception or dead-code allowlist change.

```sh
cd tools/webtransport-experiment
go test -v -count=1 -timeout 1m ./...
go test -race -count=1 -timeout 1m ./...
go vet ./...
GOOS=darwin GOARCH=arm64 go vet ./...
```

The tests create fresh in-memory ECDSA certs and a private client trust pool. Normal TLS verification stays enabled. Both endpoints bind only a local ephemeral UDP port; no cert/private-key files, fixed port or persistent listener survive. Session/accept/read/write/datagram operations have 15-second budgets, messages are exactly 32 bytes, streams require FIN, and session/transport/server teardown closes the resources. No Caddy participates.

Failing-first evidence: with the server echo body returning `echo not implemented`, session admission succeeded but `TestDirectEcho` failed after its deadline with `stream echo must be exactly 32 bytes: read 0, error deadline exceeded`. After adding echo behavior, both real-socket tests passed, including the race run:

```text
session admitted; ALPN h3; pinned draft-16 implementation (no numeric draft negotiation); current WebTransport and session flow-control settings asserted
bidirectional nonce echo passed
server-to-client unidirectional nonce echo passed
datagram nonce echo passed
HTTP/3 GET 200 succeeded; WebTransport admission refused: server didn't enable WebTransport
PASS
```

The positive pair uses the pinned draft-16 implementation with HTTP/3 ALPN `h3` and modern CONNECT `:protocol=webtransport-h3`. The server asserts the client's `SETTINGS_WT_ENABLED` (`0x2c7cf000`) and session flow-control settings (`0x2b64=1`, `0x2b65=1`, `0x2b61=1024`). The client requires the server's current WebTransport setting. There is no negotiated numeric draft field; this is observed admission/settings and source-pinned draft evidence, not a fabricated wire-version result. See immutable [protocol constants](https://github.com/quic-go/webtransport-go/blob/58c37d9b959d910e27145dd39f11df7382f9def4/protocol.go) and [client requirements](https://github.com/quic-go/webtransport-go/blob/58c37d9b959d910e27145dd39f11df7382f9def4/client_conn.go).

The negative server deliberately enables QUIC datagrams, partial stream reset and HTTP/3 datagrams, serves an HTTP/3 GET 200 and still cannot admit WebTransport because its WebTransport setting is absent. The refusal is a typed `RequirementsNotMetError`, not a timeout, TLS failure or merely a non-200 response.

**Limits:** this proves real local direct QUIC, not a rootless published Podman port or client-vantage remote reachability. Podman is unavailable here; actual rootless UDP publishing remains P08-03/P08-08. No OCI fixture was built/published. The installed **Chromium 152.0.7977.82 (Arch Linux)** is the selected available browser for a later app/probe check. Browser sessions are **unverified**; per the owner's scope correction, browser qualification is not part of this small protocol experiment. Other browser versions must be named when actually selected for an app or optional-probe drill, not inferred as compatible.

A Rust game server using default HTTP-plus-UDP readiness does **not** need Brine's echo contract. If it opts in, it must implement the bounded nonce contract (or an explicitly supported app-specific protocol) and use a tested compatible handshake. Do not turn an optional Brine probe's draft constraint into a requirement on every app or add production version-skew fallbacks.

## Endpoint, TLS and routing contract

The initial endpoint is a distinct transport origin such as `https://transport.example.invalid:24443/wt`. Documentation uses reserved example names only. The normal app page can remain on Caddy HTTPS. The app must validate the page Origin explicitly because the transport port changes the origin. Session admission, streams, datagrams, game authentication and browser/draft interoperability belong to the app. SNI identifies a certificate/domain, not authorization. Domain admission applies to both page and transport names; path text must never select an arbitrary upstream.

Direct mode preserves D4 and D2. It adds the narrow D6 exception drafted in D10. Public and tailnet listeners are separate policy cases. Never infer an all-interface bind from an app request. Multiple apps may use the same domain with different approved ports, but a future shared-443 mode needs exclusive SNI ownership and cannot distinguish apps by URL path in encrypted packets. Do not advertise `Alt-Svc` for the app's ordinary HTTP origin toward a different server merely to make WebTransport work.

Apps own their QUIC TLS identity in the initial mode. Supply only app-scoped immutable certificate and private-key secrets, not Caddy's storage, ACME account, wildcard private key, DNS token or tailnet credentials. Extend Podman file-secret injection for this purpose; rotate both references in one planned release and verify the key matches the certificate, hostname SAN, chain and expiry. Alternatively, the app may manage short-lived self-signed ECDSA certificates and publish their SHA-256 hashes to its browser through a trusted HTTPS page for `serverCertificateHashes`. That explicitly declared app-owned mode needs no Brine cert/key injection. Certificates must satisfy the browser API requirements (X.509v3, validity less than two weeks, no RSA); app-owned rotation must keep the browser hashes current. Brine must not claim normal public trust or verified certificate renewal in that mode. No silent fallback between TLS modes. The operator supplies/renews certificates through a tested runbook initially. Report expiry well before failure. Agents may install authorized certificate material through typed secret operations, but get no issuance credentials or DNS mutation rights. No private key enters plans, logs, environment output or the repository.

For tailnet-only hosts, QUIC can run over direct Tailscale IP connectivity, even when Tailscale itself relays its underlay. Do not confuse tailnet connectivity with public UDP 443. The operator controls ACL/grants and DNS. Publicly trusted certificates can use operator-side DNS-01 without public port 80 reachability; an operator-provided Tailscale certificate is restricted to its eligible node name, not arbitrary preview domains. A private CA requires client trust configuration. App-managed certificate-hash mode is an explicit application choice, never an implicit fallback for failed normal certificate verification. Its browser support and trusted hash delivery are the app owner's responsibility.

If shared-port passthrough wins later, each app still needs its own cert. Sharing one preview wildcard private key across containers is not acceptable. Caddy's automated certificate store must not be mounted into apps. Prefer eventual released session proxying for Phase 07 because it leaves public TLS and viewer authorization at the gateway. A raw SNI proxy bypasses that gateway, so private drops/previews remain refused until P08-10 proves a separate handshake authorization design.

## Current code and required changes

The baseline at **4d4ec06** is TCP/HTTP-specific. `internal/spec/spec.go` has one `ContainerPort` and HTTP `Health`; strict unknown-field validation rejects UDP declarations. `internal/policy/policy.go` normalizes one `AppPorts` range into `Desired`. `internal/quadlet/render.go` emits one loopback `PublishPort` without a protocol suffix. `internal/caddy/render.go` emits `reverse_proxy 127.0.0.1:port`; `internal/caddy/semantic.go` validates that restricted HTTP shape. `internal/caddy/generation.go` validates and publishes complete generations with ownership and unknown-reload safeguards. `internal/apply/health.go` uses `net/http`, normal TLS verification and local routed dialing. It cannot exercise WebTransport.

`internal/enroll/engine.go` journals fixed steps; `internal/enroll/host_linux.go` and package steps install the runner/runtime, restricted SSH, import and reload-only policy. They do not change firewalls. Preserve that limit. Also update `internal/target`, `internal/inventory`, `internal/plan`, `internal/store`, host composition, diagnostics and status consumers together. A scalar port, TCP listener scan or stored HTTP health result cannot prove UDP ownership or WebTransport health.

### Planned data shape

Keep the ordinary HTTP app contract. Add one optional typed `webtransport` endpoint, not generic Podman flags or arbitrary network bindings. Initial mode is `direct_udp`; reserve no silently accepted unsupported modes. The endpoint contains container UDP port, approved transport domain and explicit TLS ownership (`file_secrets` with certificate/key version references, or `app_managed_hashes` with app-owned hash delivery and rotation). Session path and bounded echo details are required only for the optional protocol-health mode. The default readiness contract remains ordinary app HTTP health plus verified ownership of the expected UDP mapping/listener. Return protocol readiness and external reachability as unverified unless a separate probe actually establishes them. Host bind address, public/tailnet exposure and allocated UDP port come from root-owned operator policy, not app-supplied addresses. Return the resulting full endpoint URL after commit.

Normalize TCP/UDP allocations as `(protocol, bind address, host port, resource incarnation)` records. Canonical desired input, plan hash, observed generation, releases, retained rollback artifacts and stale checks bind all fields plus TLS mode, certificate version references when delivered by Brine, selected health mode and ingress capability/build identity. Existing HTTP apps change neither their ingress nor semantics. Update source and consumers together; do not add old-client/new-server compatibility branches.

WebTransport policy defaults to denied. It explicitly allows the protocol, app/domain scope, UDP range, exact bind addresses, exposure class, certificate references and UDP allocations. Session/stream/datagram limits belong to the app; Brine enforces bounded limits on its own optional probe, not the game traffic. Direct mode uses ports at least 1024. Shared UDP 443 belongs only to an operator-enrolled ingress, never to arbitrary app publishes. Deny host networking, sockets, additional capabilities, app-selected public addresses and broad certificate access.

## Exit gates

Initial app-owned direct-UDP support requires P08-01 through P08-04, P08-06 and P08-08. The physical drill proves UDP publishing, scoped cert delivery or explicit app-owned certificate lifecycle, default HTTP-plus-UDP readiness, both architectures and owned cleanup/recovery. P08-05/P08-07 and browser streams/datagrams qualify the optional protocol health mode separately. Do not label default readiness as verified WebTransport, and do not block an ordinary-health Rust game server on a Brine echo contract.

Shared-port support requires P08-09 separately. WebTransport drops/previews require P08-10 separately. Report their status distinctly in release notes and diagnostics. Every supported mode needs a certificate renewal procedure, owned cleanup, policy refusal tests and interruption recovery. No option expands agent access to firewall, DNS, Tailscale, raw Caddy or an unrestricted shell.
