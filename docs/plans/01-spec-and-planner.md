# Phase 01: App specification and planning

**Depends on:** Phase 00 response and command contracts. **Goal:** reproducible, side-effect-free intent. No Podman/Caddy required to test.

### Tasks

- [x] **P01-01** Introduce strict, versioned `brine.toml` parser with fixture examples. Reject unknown fields, duplicate keys, bad app names, invalid domain labels, arbitrary paths, unpinned image tags, malformed digests, unsafe ports, invalid health paths, and unsupported options.
- [x] **P01-02** Normalize desired app configuration and enforce an explicitly supplied target policy: registries, domains, persistent roots, secret references (D5), app port range (D6) and resources. Reject unsafe environment expansion and shell/Quadlet pass-through. Evidence: `internal/policy` strict operator TOML decode, typed category-4 refusals with zero desired output, canonical policy hashes and desired JSON, registry/domain/secret/resource boundary tables, shuffled collection determinism, and policy decode fuzzing. The range defaults to 20000–20999; allocation remains planner/host work. Persistence roots are validated and hashed for later phases; the v1 spec cannot request mounts. Required checks and `go test -race ./...` pass.
- [x] **P01-03** Define stable plan types for create/update/no-op/conflict, ordered changes, expected runtime image/platform and durable immutable plan hashes. Exclude wall-clock timestamps from plan fingerprints; include target generation and policy version. Evidence: pure `internal/plan.Build`, typed change payloads, deterministic allocation and immutable secret-version bindings. The contract documents exact desired/config/plan hash material. Live domain/listener ownership is part of the target snapshot; committed releases and previous normalized configuration are a separate, identity/generation-bound `BrineState` input. Required runtime/readiness observations fail closed, and secret-only records cannot authorize replacing namesake files. Fixture matrix covers create, no-op, image/domain/environment updates, required conflicts, missing observations, artifact drift and secret rotation. Canonical golden JSON, shuffled nested sets, input/output ownership and hash-property fuzz tests cover T03; identity/generation/policy fingerprint tests cover the T04 precondition only. Required checks and `go test -race ./...` pass. No CLI, storage, apply or host verification is claimed.
- [x] **P01-07** Define the versioned target snapshot schema (OS, arch, runtime versions, owned units, Caddy files, used ports, allocated app ports, secret IDs, generation, live Caddy domains and port owners). Offline plans read it, and P02-01 inventory must emit exactly this type. Evidence: `internal/target` strict decoding, canonical round trips for eight fixtures, independent Caddy-generation/file-set and passt observations, ordering and rejection tests. Snapshot ownership extensions add live-file address normalization, strict owner fields and runtime-readiness fixtures. Current release IDs belong to the separate Brine control-database state, not inventory.
- [ ] **P01-04** Add read-only `validate` and `plan --offline` with fixture target snapshots. Offline plans must be conspicuously **not applyable**; never silently treat a fixture as a connected host.
- [x] **P01-05** Write offline plans as content-addressed plan files marked not applyable. No control database in this phase; it lives on the target and arrives in P03-01 (D1). Evidence: `internal/planfile` immutable offline envelope, caller-supplied creation metadata outside the plan hash, retained verification inputs, strict bounded decoding and typed schema/integrity/conflict errors. Files use hash-derived names and mode 0600, with same-directory temporary writes, file/directory fsync and atomic no-replace publication. Tests cover round trips, single-byte tampering, secret-value field rejection, missing or forged offline markers, overwrite conflicts, identical retries, filename binding, injected failures and concurrent writers. Required checks and `go test -race ./...` pass. No CLI wiring, host database or apply authority is added.
- [x] **P01-06** Run property/fuzz tests over names, paths, image digests and canonical ordering. Add readable human diff and deterministic JSON output from one plan model. Evidence: `internal/planview` renders documented, redacted JSON and themed, width-bounded human diffs from `plan.Plan`, with plain create/update/no-op/conflict goldens. The hashed typed configuration diff retains actual prior image/platform, ports, health, resources and secret names/versions from `BrineState`; domains and environment keys record additions/removals, with changed environment keys only. Literal environment values never enter the returned plan, including Quadlet payloads. Generated and native fuzz tests cover normalization idempotence, path safety, input/presentation permutations, sampled hashed-field changes, comparison hash inclusion, memory ownership, digest-prefix collisions, NO_COLOR, 40/80-column output and planted private values. Required checks and `go test -race ./...` pass. No host, CLI wiring or apply verification is claimed.

### Exit gate

Same configuration + target snapshot + policy produces the same plan hash and change ordering. An invalid or hostile spec never produces an applyable plan. `validate` and offline `plan` do not contact, alter or provision infrastructure.

**Evidence:** T02, T03, T17, T23; fixture snapshot cases for no-op/create/update/conflict; tests prove no adapters capable of mutation are called.
